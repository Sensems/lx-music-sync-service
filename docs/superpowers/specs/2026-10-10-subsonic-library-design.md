# Postgres 曲库与 Subsonic

日期：2026-10-10  
状态：待审阅

## 目标

把听柜从「SQLite 上的歌单同步器」换成「PostgreSQL 上的单用户曲库服务器」。对外提供 Subsonic / 一小段 OpenSubsonic，对内用三条入口把歌送进同一套表：订阅在线歌单、搜索点歌、扫描本地目录。

播放地址继续走现有音源沙箱。歌曲、歌单、歌词、封面的在线抓取继续走现有 `musicSdk`、歌词和封面刮削。

## 非目标

- 不改 Vue 页面。现有网页绑的是歌单同步接口，接到新管理接口上另写一份设计。
- 不把旧 SQLite 数据迁进 Postgres。`data/` 里的旧库留在原地，新曲库从空库开始。
- 不实现用户管理、播客、网络电台、分享、点唱机、聊天、转码。
- 不按年份、风格、评分编造专辑列表；这些 Subsonic 类型返回空的成功结果。
- 不为新模型补单元测试。
- 不改音源沙箱的边界：加载超时 5 秒、取地址超时 20 秒、禁用 `require`、返回值必须是 http(s)、不把 `fs` / `process` / 真实 `require` 放进沙箱。
- 默认监听地址仍是 `127.0.0.1`。Node 仍是单进程，PM2 仍是 `instances: 1`。

## 保留与替换

留下并继续调用：

- `src/userApi`：把一首已有平台身份的歌解析成播放地址。
- `src/sdk/musicSdk` 以及歌词、封面刮削：搜索、在线歌单、歌曲详情、歌词、封面。

替换掉：

- SQLite、`playlist_tracks` 式快照、以「下完的文件」为库的同步队列。
- 现有 `/api/playlists`、`/api/sync`、`/api/jobs`、`/api/downloads` 这组歌单同步接口。

## 曲库模型

Postgres 里一首歌一行。主键用 `bigint`，Subsonic 看到的 id 是它的十进制字符串。一首歌可以有零到多条平台身份，以及零个或一个当前本地文件。歌手、专辑单独成表。歌单只保存歌曲 id 和顺序。

表：

| 表 | 职责 |
| --- | --- |
| `artists` | 歌手。名字先去掉首尾空白、把连续空白收成一个空格，再按这个名字唯一 |
| `albums` | 专辑。身份是专辑歌手 + 专辑名。专辑名先去掉首尾空白、把连续空白收成一个空格，再参与比较 |
| `album_sources` | 平台专辑 id，挂到 `albums`。同一平台同一专辑 id 只指向一张专辑，再次出现时仍挂在第一次写入的那张上 |
| `songs` | 标题、时长（毫秒，可空）、音轨号、碟号、歌词文本、歌词译文 |
| `song_artists` | 歌曲与歌手的顺序。第一位歌手是专辑歌手 |
| `song_sources` | 平台 + 平台歌曲 id + 刮削原文。`(platform, platform_song_id)` 唯一 |
| `media_files` | 当前文件的路径、大小、mtime、音质、是否缺失。一歌一行 |
| `library_roots` | 扫描根目录 |
| `playlists` | `kind` 为 `subscription` 或 `user`。订阅歌单另存来源 URL 与平台 |
| `playlist_items` | 歌单内的歌曲 id 与顺序 |
| `stars` | 收藏对象：歌曲、专辑或歌手 |
| `scrobbles` | 一次 `submission=true` 的播放。播放次数按歌曲计数得出 |
| `jobs` | 后台任务：类型、状态、错误摘要 |
| `settings` | 音质、音源顺序、定时、Subsonic 用户名和口令摘要 |

合并规则：

- **强匹配**：同一平台、同一个平台歌曲 id，是同一首歌。
- **中等匹配**：标题、专辑歌手、专辑名、时长都有，且时长差不超过 2 秒，合并成一首，并把新的平台身份挂上去。
- 缺少时长、专辑名或专辑歌手时，不做中等匹配。
- 只有标题和歌手相同，保留为两首歌。
- 歌手或专辑为空时，使用「未知歌手」「未知专辑」。
- 刮削得到的歌手字符串按 `/`、`、`、`,` 拆开。第一位是专辑歌手，其余按顺序写入 `song_artists`。

本地文件用路径、大小、mtime 标识。标签里若有平台和平台歌曲 id，走强匹配。否则在标题、专辑歌手、专辑名、时长都齐全时走中等匹配。对不上就新建一首只有文件的歌。

一首歌只保留一个当前文件。新文件匹配到已有歌曲时：原文件还在，就保留原文件，这次扫描把新文件记为未并入；原文件已缺失，用新文件补上并清掉缺失标记。

## 三条入库

三条入口调用同一个入库函数。订阅和搜索都不自动下载音频。

1. **订阅歌单**  
   用现有歌单刮削把曲目拆成歌手、专辑、歌曲，再替换该歌单的 `playlist_items`。整份歌单都刮成功才替换；中途失败保持上一份成员，任务记失败。歌从在线歌单消失，只移出这份歌单，歌曲行保留。

2. **搜索点歌**  
   用现有搜索刮削。选中的一首走同一入库函数，可以不属于任何歌单。单曲入库在请求里完成，不进后台队列。

3. **扫描目录**  
   `library_roots` 里的目录逐个走音频文件。读不了的文件跳过并记入任务，不改动其他已入库的歌。文件不见了：把 `media_files` 标成缺失，不删歌曲行。还有平台身份时仍可走音源；没有平台身份时播放返回 404。不另设「不可用」状态列。

缓存目录不是扫描根。扫描不会把缓存文件再扫成另一首歌。

## 播放、缓存、歌词和封面

`stream` 与 `download` 共用一条打开路径，支持 Range，不转码。

1. 当前文件存在且未标缺失：按文件原样送出。
2. 没有可用文件、但有平台身份：按设置里的音源顺序挑第一条当前脚本支持的身份，用音源沙箱取 `musicUrl`。默认顺序是酷我、酷狗、QQ、网易云、咪咕。地址只在内存里按「歌曲 id + 音质」缓存，过期或对端不返回音频就丢掉再取一次。
3. 没有文件、也没有可用平台身份：404。

目标音质来自设置。脚本不支持时沿 `flac24bit → flac → 320k → 192k → 128k` 往下退。已缓存的文件不会因为目标音质调高而自动重下。单独的「按当前音质重新缓存」下完后替换 `media_files` 指向的文件。

缓存是单独动作，对象是一首歌或一份歌单。文件写到数据目录下的缓存文件夹，路径以 `media_files` 为准。歌单变短时不删已缓存文件。

入库时把刮削到的封面地址记在专辑上，歌词先空着。第一次请求封面或歌词时再刮：封面存成文件，歌词写入 `songs`。刮失败则这一次为空，歌曲仍留在库里。

音源临时失败（脚本未加载、超时、链接失效）只让这一次播放失败。歌曲留在库里，下次播放再试。

## Subsonic

挂在同一进程的 `/rest/*.view`。同一份数据输出 JSON（`f=json`）和 XML。API 版本声明为 `1.16.1`。`getLicense` 返回有效许可，避免客户端因许可检查而拒绝连接。OpenSubsonic 只声明并实现 `getLyricsBySongId`。

### 鉴权

一个用户，口令只存摘要。客户端可以传口令参数，也可以传 salt + token（`md5(口令 + salt)`）。

口令未设置时，只有来自回环地址的请求能通过。来自其他地址的请求一律鉴权失败，即使进程听在 `0.0.0.0`。

### 浏览

一个音乐文件夹，里面是整座曲库，包括尚未缓存的歌。`getIndexes` / `getMusicDirectory` 与 `getArtists` / `getArtist` / `getAlbum` 读同一批歌手和专辑：文件夹下面是歌手，歌手下面是专辑，专辑下面是歌曲。

`getAlbumList2` 里，按名称、按歌手、最新加入、最近播放、播放最多、随机、已收藏使用真实记录。按年份、按风格、按评分返回空列表且状态为成功。

### 歌单、搜索、收藏、播放记录

- 订阅歌单可以 `getPlaylists` / `getPlaylist`。`updatePlaylist` / `deletePlaylist` 对 `kind=subscription` 返回失败（错误码 50）。刷新成员只走管理接口。
- `createPlaylist` 以及针对 `kind=user` 的更新、删除，只改用户歌单。
- `search2` / `search3` 只搜库内歌曲、专辑、歌手。在线搜索不是 Subsonic 搜索。
- `star` / `unstar` 的对象是歌曲、专辑、歌手。
- `scrobble` 在 `submission=true` 时写入一条 `scrobbles`。播放次数就是该歌曲的记录条数。`submission=false`（正在播放）不写记录。

### 接口

登录和浏览：`ping`、`getLicense`、`getUser`、`getMusicFolders`、`getIndexes`、`getMusicDirectory`、`getArtists`、`getArtist`、`getAlbum`、`getSong`、`getAlbumList2`、`getStarred2`、`getRandomSongs`。

播放和检索：`stream`、`download`、`getCoverArt`、`getLyrics`、`getLyricsBySongId`、`search2`、`search3`。

歌单和状态：`getPlaylists`、`getPlaylist`、`createPlaylist`、`updatePlaylist`、`deletePlaylist`、`star`、`unstar`、`scrobble`。

订阅网址、扫描目录、缓存、音源脚本都不通过 Subsonic 进入。

## 管理接口

进程内的 HTTP 接口，供以后的网页使用。这次只提供接口，不改页面。

- 订阅：添加 URL、列表、刷新、删除订阅（删除订阅不删歌曲、不删缓存文件）。
- 搜索：沿用刮削搜索；选中一首则入库。
- 目录：添加、删除、触发扫描。删除目录只去掉根，不删已经入库的歌。
- 缓存：缓存一首、缓存一份歌单、按当前音质重新缓存。
- 音源脚本：沿用现在的上传和 URL 安装。
- 设置：目标音质、音源顺序、定时、Subsonic 用户名和口令。

## 任务、失败与部署

`config.yaml` 增加 Postgres 连接串。启动时执行仓库里的 SQL 迁移。

后台任务同一时间只跑一个，排在一条队列里：刷新订阅、扫描目录、缓存。点播取地址不进这条队列。订阅刷新沿用现有定时设置。扫描默认为手动，也可以挂到同一定时。

部署仍用 PM2 单实例。服务器另备 Postgres。把 `host` 改成非回环地址之前，先写上 Subsonic 口令；没写口令时，非回环请求过不了鉴权。

## 实现顺序

1. Postgres 表、迁移、入库函数与三条入口。
2. 播放、缓存、歌词和封面落盘。
3. Subsonic 登录、浏览、播放、封面、歌词。
4. Subsonic 歌单、搜索、收藏、scrobble。
5. 管理接口、定时、部署说明。去掉旧的歌单同步接口。

网页改版不在这一份里。

## 验收

不新增单元测试。下面五件事手动走通即可：

1. Subsonic 客户端能登录。
2. 能按歌手和专辑翻到库里的歌。
3. 有本地文件时播放的是文件。
4. 没有文件、有平台身份时播放走音源。
5. 订阅刷新中途失败时，歌单成员仍是上一份。
