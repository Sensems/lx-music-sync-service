# 听柜播放器

日期：2026-09-19  
状态：已批准

## 目标

1. 去掉唱片墙点击封面打开歌词抽屉的交互与逻辑。
2. 增加全局音乐播放器，同一套状态、四种界面形态。
3. 播放源：本地已下载文件优先；没有文件则用用户音源脚本解析在线试听地址。
4. 支持「只播一首」「播放当前歌单」「加入队列」。

## 非目标

- 收藏、自建歌单编辑、均衡器、定时关闭、多设备投播。
- 不把任务条（SyncRibbon）改成播放器；任务条仍贴页面最底。
- 不改默认监听地址、不引入多进程。
- 刷新页面后不自动续播。
- 不删除本地音频文件。

## 唱片墙

- 点击封面不播放、不拉歌词、不开 Drawer。
- 点击封面后仅在该封面叠一层操作：
  - **播放**：队列替换为这一首并开始播放，播完停止。
  - **加入队列**：见下方队列规则。
- 再点同一封面或点空白处收起操作层。点另一张封面则改到那一张上，不累加多层。
- 引导文案改为说明「点封面会出现播放」。

## 歌单页

- 当前打开的歌单标题区增加 **播放歌单**：用该歌单全部曲目**替换**当前队列，从第一首开始播。队列里只有这一张歌单的歌，不混入唱片墙或其他歌单。
- 每一行增加 **播放**（只播这一首）和 **加入队列**。
- 「同步」等原有操作不变。歌单为空时「播放歌单」不可用。
- 播放未下载曲目时，前端带上该曲的 `songKey` 与 `raw`/`musicInfo`（接口已有），供 `POST /api/stream` 使用。

## 搜索页

- 每一条搜索结果增加 **播放**（只播这一首）和 **加入队列**。
- **下载**按钮保留。

## 队列规则

| 动作 | 队列 | 是否打断当前播放 |
| --- | --- | --- |
| 播放（单曲） | 替换为这一首 | 是，立刻播这首 |
| 播放歌单 | 替换为当前歌单全部曲目 | 是，从第一首开始 |
| 加入队列（队列空） | 加入这一首并开始播 | — |
| 加入队列（队列非空） | 接到末尾 | 否 |
| 加入队列（`songKey` 已在队列） | 不重复添加 | 否，轻提示 |

全屏播放器可查看队列、删除某一首、点击某一首跳播。上一首 / 下一首只在当前队列内移动。队列只剩一首时上一首 / 下一首禁用。

## 四种形态

同一个播放器组件，按状态切换布局。页面纵向叠放：内容 → 播放条 → 任务条。全屏与车载盖住任务条。

1. **底部条**  
   有当前曲且未展开时显示，贴在任务条上方。左：封面、歌名、歌手；中：播放 / 暂停；右：时间、展开。顶边一条进度。点播放 / 暂停不展开；点条的其余区域或封面向上展开。

2. **全屏**  
   底部条展开后自下而上铺满视口。大封面、随进度滚动的歌词、进度条、上一首 / 下一首、循环、随机、音量、队列、车载入口。下滑或点收起回到底部条。

3. **移动端**  
   视口宽度约小于 768px 时，仍是底部条 / 全屏两套状态，只换排版：底条更矮、触控更大；全屏为上封面、中歌词、底下一排大按钮，音量收进更多菜单。

4. **车载**  
   仅从全屏进入：点「车载」。超大上一首 / 播放 / 下一首，字号加大，歌词弱化。再点「车载」或「返回」回到全屏。不自动根据横屏进入。车载是显式开关，窗口变窄也不自动退出。

队列为空且没有当前曲时不显示播放条，页面底边距只留给任务条。

## 播放功能

第一版必须有：

- 播放 / 暂停
- 进度拖动，当前时间 / 总时长
- 音量、静音
- 上一首 / 下一首
- 循环：关 / 单曲 / 列表
- 随机
- 队列面板
- 全屏滚动歌词（解析 LRC，按进度高亮当前行）
- Media Session（系统媒体键、锁屏控件）

音量、循环模式、随机写入 `localStorage`（键名 `tingui-player`）。不持久化队列与播放进度。

## 取流与歌词 API

现有 `GET /api/lyrics?songKey=` 只服务已下载记录。播放器需要未下载曲目也能试听和看词。

**取流**

- `GET /api/stream?songKey=`：库里已有下载记录时使用。
- `POST /api/stream`：body 与下载接口相同，接受 `musicInfo`（或 `source`+`id`）。用于搜索结果、歌单里未下载的曲。

行为：

1. 若 `downloads` 有该 `songKey` 且本地文件存在：按 `Range` 输出文件，`Content-Type` 按扩展名。
2. 否则调用现有 `getMusicUrl` 解析地址，由服务端把远端音频转发给浏览器（避免 `<audio>` 跨域 / Referer 问题），尽量透传 `Range`。
3. 解析失败或非 `http(s)` 地址：4xx/5xx JSON `{ error }`。
4. 仍然单进程、不把 `fs` 暴露给音源沙箱。

**歌词**

- 保留 `GET /api/lyrics?songKey=`。
- 增加 `POST /api/lyrics`，body 为 `musicInfo`，内部走现有 `getLyricForMusic`。已下载记录仍可只传 `songKey`。

前端 `<audio>` 的 `src` 只指向本服务 `/api/stream...`，不把音源直链写进页面。

## 前端结构

- 全局播放状态：一个 composable / 单例（如 `web/src/player/usePlayer.ts`），在 `App.vue` 挂播放器壳。
- 不引入第三方播放器组件；用原生 `HTMLAudioElement`。
- 主题继续用现有 CSS 变量，不另做一套皮肤。
- 测试：HTTP 用 `createApp(ctx)` + `app.fetch`；流接口用临时文件测 Range，用假 `getMusicUrl` 测在线回退。前端 `vue-tsc` / `web` build。不测真实平台。

## 文案

面向用户的按钮用短词：播放、加入队列、播放歌单、车载、返回。失败时说人话（「暂时没有可播放的地址」），不堆技术细节。
